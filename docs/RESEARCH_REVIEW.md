## 완료와 미완료를 혼동하기 쉬운 항목

- 5단계 분석 완료 ≠ 현장 최적 운전 검증 완료임. 관측 범위 내 결과와 내부 검증까지 확보된 상태임.

- 평가문항20개 준비 ≠ LLM 정확도 검증 완료임. 실제 모델 응답·채점 결과가 필요함.

- 검색 recall@10=13/15라는 개발 보고 ≠ 20문항 정답률 또는 추천 정확도임.

- 약품 탄소/전력계수로 계산한 kWh-equivalent ≠ 실제 교반 전력 절감량임.

- 현재 구조는 Claude API·TF-IDF·규칙 추천으로 보고되어 있음. Local LLM·Vector DB·DSPy 전체 구현 완료로 표현하면 안 됨.

# 5. 과학적 해석·계산의 우선 점검



| 점검 항목 | 확인된 문제 | 다음 행동 |

|---|---|---|

| TS/VS | VS>TS21/26, 음의TS2건; VS 반복 CV 최대78.6% | 운영 추천에서는 분리; blank·반복 검증 또는 탐색 한계 유지 |

| Jar·지역 | 조건당1회; 굴화 재상승7/12지만 평균ΔNTU는 음수 | 재상승 빈도·평균변화 분리, 원수 차이의 원인 단정 금지 |

| 추천 범위 | 탁도±30%만으로 유사 실험 선택하는 구현 보고 | 지역·시점·지원 응집제 표시, 미충족/미보유 입력 거절 |

| 전력 | 약품 제조 탄소를 kWh로 환산한 값 사용 | 전력환산 카드 명칭 수정; 교반·펌프 전력 별도 계산 |

## 추가 실험의 결정 기준

- 11/28까지 시료·장비·담당·측정 항목·독립 반복 가능성을 확인함. 가능하면 선택한 조건의 재현성과 질량 QC를 12/2까지 검토함.

- 가능하지 않다면 전체 재실험을 무리하게 일정에 넣지 않고 관측 탐색 결과로 범위를 제한함.

- 실험을 다시 하지 않는 선택은 오류가 해결됐다는 뜻이 아님. 주장 범위의 축소와 함께 기록해야 함.

- 공정 계산의 최소식은 약품 kg=D(mg/L)×Q(m³)/1000, 전력 kWh=P(W)×t(h)/1000임. 동력·효율·질량 기준의 추가 조건은 ENERGY_SPEC에 명시함.

# 6. LLM 평가·DSPy의 남은 단계

## 평가를 실제 결과로 바꾸는 순서

- ① Gold 검수 → ② 같은 모델·자료 접근·출력 형식 고정 → ③ 시범평가 → ④ 오류 수정 후 버전 고정 → ⑤ 실제 응답·인간 채점·오류표 확보 순서임.

- 기본 점수는 정답1점+근거1점, 총40점이며 실험10/문헌10 결과를 분리함. 틀린 선택지의 근거점수 처리도 미리 정해야 함.

- 자료 없는 모델과 자료 있는 전체 시스템 비교는 시스템 전체 효과임. 추론 자체 개선을 주장하려면 정보 접근 조건을 통제한 비교가 필요함.

- 원시 데이터·문헌 원문은 사용 가능한 지식임. 정답표·문제은행·평가용 정답을 포함한 분석 보고서는 후보 시스템 입력에서 제외함.

## DSPy의 정확한 위치

- 원래 선택안은 심사위원 채점 프롬프트의 자동 최적화임. 답변/추천 모델을 최적화했다는 주장과 구별해야 함.

- 실제 모델 응답에 사람이 부여한 점수·근거가 필요함. 정답 선택지만 가진 상태는 심사위원 최적화의 충분한 준비가 아님.

- 별도 보정자료가 확보되면 11/30–12/1에 구현·고정하고 최종 평가와 분리함. 확보되지 않으면 수동 루브릭과 인간 평가를 우선함.

- 현재20문항은 이미 알려진 소규모 평가안임. 이 문항으로 튜닝했다면 독립 시험 성능으로 표현하지 않음.

## 문헌·앱 검수에서 남은 공백

- Tunç(2020)·Abdo(2023)의 문제·정답·인용은 있으나 해당 논문 원문 PDF는 현재 Drive 목록에 없음. 실제 평가 전 원문 대조가 필요함.

- 추천 규칙·계산기·없는 날짜 응답·실제 API 연결은 별도 기능 검증이 필요함. MCQ 점수로 대신할 수 없음.

| docs/*_SPEC / *_PROTOCOL | 데이터·에너지·평가에 공통으로 적용할 규칙 |

| templates/ | 회의 결정·작업 인수인계·일일 변경 기록 |

| scripts/ | 진행표 자동 갱신과 일정·의존관계·범위 점검 |



- tasks.csv 수정 후 python scripts/update_trackers.py를 실행하면 전체 진행표와 개인별 역할표가 함께 갱신됨.

- python scripts/check_plan.py로 시험기간 중 업무·잘못된 선행 ID·날짜·의존순환·자료 목록 누락을 확인함.

- Git에 익숙하지 않은 팀원은 Drive에 결과+코드+설명을 전달하고 통합 담당이 반영하는 방식으로 운영 가능함.

- 참고 저장소의 README·PROGRESS·TEAM_TASKS 중심 구조를 적용함. 원 연구의 과학적 내용이나 담당을 복사한 것은 아님.
