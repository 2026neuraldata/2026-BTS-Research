## GPT·Claude·Gemini 중 무엇을 선택할지

- **11/27까지 주 심사위원 1개와 다른 제공사의 교차 심사위원 1개 선정.** 세 제공사를 모두 최종 평가의 필수 심사위원으로 운영하지 않음.
- GPT·Claude·Gemini에서 실제 계정으로 호출 가능한 텍스트 모델을 각각 1개 선택하고, 정확한 모델 ID와 버전을 기록. 제품 이름만 적고 다른 버전을 섞지 않음.
- 보정셋은 정답·오답·맞는 근거·잘못된 근거·무응답을 포함한 최소 12개 실제 답변. 최종 평가 문제와 같은 문제군을 피하고, 모델 이름을 가린 상태에서 사람이 먼저 채점.
- 사람 2명의 독립 채점 후 조정한 점수를 기준으로 후보 심사위원의 **점수 평균 절대오차(MAE), 정확히 같은 점수를 준 비율, 형식/호출 실패율**을 비교. 보정셋은 모델 선정 자료이며 독립 성능 결과로 보고하지 않음.
- 실패가 있는 후보는 원인을 먼저 확인. 정상 동작 후보 중 사람 점수와의 차이가 작고 일치율이 높은 후보를 우선 선택. 차이가 뚜렷하지 않으면 비용·응답 시간과 다른 제공사 사용 여부를 함께 고려.
- 답변 모델이 Claude이면 Claude 심사위원 결과에는 같은 제공사에 대한 선호 가능성이 있으므로 별도 표시. 다른 제공사도 편향이 없다고 가정하지 않으며, 교차 심사위원과 사람의 판단을 함께 비교.
- 최종 답변에 유리한 점수를 준다는 이유로 심사위원을 고르지 않음. **선정은 최종 평가 전에 완료.** API 접근·비용 문제로 후보를 실행하지 못하면 미실행으로 남기고 선정 근거에 반영.
- 모델 카탈로그와 계정의 실제 사용 가능 여부를 11/27에 확인: [OpenAI](https://developers.openai.com/api/docs/models), [Anthropic](https://platform.claude.com/docs/en/models/overview), [Google](https://ai.google.dev/gemini-api/docs/models).

## 심사위원에게 무엇을 평가시킬지

1. **정답 선택지:** 정답표와 일치 여부로 결정. LLM의 주관적 판단에 맡기지 않음.
2. **근거 점수:** 질문·답변·검수된 정답 근거·고정 채점 기준을 제공하고 0/1점 및 짧은 사유 기록. 사람 채점과 비교.
3. **G-eval 방식의 품질 평가:** 정확성·근거 충실성·조건/단위 준수 각각 1–5점. 1=핵심 오류, 3=일부 누락, 5=기준 충족의 문항별 예시를 작성. 2점 정답/근거 점수와 합산하지 않음.
4. **Pairwise 비교:** 동일 질문의 두 답변을 이름 없이 제시하고 우수 답변 또는 동률 선택. 응집 전문 시스템과 각 일반 LLM 조건을 따로 비교. A/B 순서를 바꿔 2회 평가하고 판단이 바뀐 경우 순서 불일치로 기록.
5. **교차 검증:** 다른 제공사의 심사위원이 같은 답변을 채점. 주 심사위원·교차 심사위원·사람의 점수를 각각 보고하고 불일치 사례는 사람이 검토.

- 답변 수집 20문항×3조건=60개 응답을 기본 1회 실행으로 설정. 사람·심사위원은 같은 저장된 답변을 사용. 반복성 검증은 별도 실행 수를 미리 정한 경우에만 수행.
- Pairwise는 전문 시스템 대 일반 조건 2종×20문항×순서 2종=심사위원당 80판정. 실행 전 예상 호출량과 비용을 계산.
- 최종 평가 20문항이 개발에 이미 쓰였다면 소규모 개발셋 평가로 표기. 문제 수나 모델별 반복 수를 독립 표본 수로 부풀리지 않음.

## 서로 다른 세 종류의 검증

| 검증 | 주 지표 | 범위 |
|---|---|---|
| MCQ 답변 | 정답 수/20, 정답점수·근거점수 각각20점, 합계40점 | 응집 자료에 근거한 답변 정확성임 |
| 문헌 검색 | recall@k, 정답 페이지·실제 검색어·청크 | 기존13/15@10은 개발 보고값이며 별도셋임 |
| 추천·계산 기능 | 고정 입력의 기대 후보·거절·단위·산식 일치 | MCQ 성적만으로 대체할 수 없음 |

## 비교 설계

- 같은 기반 모델 ID·버전, 응답 설정, 언어, 출력 형식, 평가 문항을 사용함.
- A: 자료가 추가되지 않은 기반 모델은 참고 비교로 둘 수 있음. C와의 차이는 자료 접근을 포함한 시스템 전체 효과임.
- B: 동일 원문·원시 데이터 또는 동일한 근거 문맥을 제공받는 기준 모델임.
- C: 실험 조회·검색·규칙·계산을 사용하는 전체 시스템임.
- 주 비교의 B/C 정보 접근 수준을 명시함. ‘같은 원문 접근’과 ‘같은 실제 검색 문맥’을 같다고 취급하지 않음. 후자는 답변 단계만 비교하는 보조 실험으로 분리 가능함.
- C에만 분석 정답표를 주고 추론 능력의 향상으로 해석하지 않음. 원시 실험표와 문헌 원문을 제공하는 자체는 정답 누출이 아님.
- 시스템과 사람이 모두 알고 있는20문항은 제한된 평가임. 이 문항으로 디버깅·최적화했다면 개발셋 사용 사실을 명시하고 독립 최종 검증이라고 부르지 않음.

## 자료 분리

- candidates_allowed: 원본 Jar 데이터, 검수된 문헌 원문, 비정답형 산식·단위임.
- candidates_excluded: 평가 문제은행, 정답표, 인간 채점결과, 평가용 정답을 재서술한 분석 보고서임.
- judge_allowed: 질문, 응답, Gold 근거, 고정 루브릭임. 짧은 채점 사유와 출처만 저장하면 되며 내부 추론 전체가 필요하지 않음.
- 140개 후보은행은 기존 분석에서 파생된 유사 문제를 포함함. 무작위 행 분할만으로 독립 보정/시험 셋이 되지 않음.
- split_manifest에는 문항·원문/문제군·유사문항·사용 목적(calibration/development/test)을 기록함.

## 2점 채점 기준

- 선택지 정답1점 + 출처·조건·계산이 맞는 근거1점임. 틀린 선택지는 근거점수0점으로 처리하는 규칙을 평가 전에 고정함.
- 정답 선택지만 내면1점임. 근거점수는 Gold에서 요구한 핵심 조건을 충족해야 함.
- 문항당 최대2점, 전체40점임. Q1–10과Q11–20을 각각 보고함.
- 호출 실패·무응답을 숨기지 않음. 답변정확도 분모에는 전체 예정 문항을 유지하고 시스템 실패율을 함께 제시함. 재시도 정책·횟수를 먼저 고정함.
- 단일 실행 결과는 실행 간 변동성을 보여주지 않음. 반복 실행 시 횟수를 먼저 고정하고 문항별 반복을 독립 문항 수로 부풀리지 않음.
- 20문항은 작고 문제군 의존성이 있을 수 있으므로 근소한 점수 차이만으로 일반적 우월성을 선언하지 않음.

## 심사위원·DSPy

- 원래10월 선택안의 DSPy 대상은 **심사위원의 채점 프롬프트**임. 추천 모델 자체의 최적화와 구분함.
- 보정자료는 실제 모델 응답에 사람이 매긴 점수·근거여야 함. 정답 선택지 목록만으로 사람과의 채점 일치를 최적화할 수 없음.
- 보정/개발과 분리한 응답에서 수동 프롬프트 대비 점수 차이·판정 일치를 평가함. 그 결과가 없으면 최적화 효과를 주장하지 않음.
- G-eval의1–5점과 인간2점 채점은 별도 척도로 보고함. 사전 근거 없이 하나의 합산점수로 섞지 않음.
- pairwise는 A/B 이름을 가리고 순서를 바꿔 평가함. win/tie/loss, 분모·순서 불일치를 기록함. 점수가 높은 답을 단순 선택한 결과와 독립 pairwise 판단도 구분함.

## 고정 입력 기능 점검

- 정상 목표 충족, 동률 최소dose, 목표 미충족, 원수 범위 밖, PAC/Alum 실험 없음, 지역 선택, 5/30분 선택을 확인함.
- 문헌 수치의 pH·원수·약품·단위를 함께 확인함. 문헌 쪽 번호는 PDF 실제 쪽과 인쇄 쪽을 구분함.
- 에너지 누락 입력·상충 계수·단위 변환·음의 절감(증가)을 확인함.
- 실제 API 연결 평가와 mock 테스트를 따로 보고함.
