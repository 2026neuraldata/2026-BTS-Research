## 무엇이 바뀌었나

| 완료 기준 | 반영 내용 |
|---|---|
| 기존 Excel·명목 dose 대체 금지, 80.16 정밀도 보존 | 앱이 Excel 대신 D02 `jar_conditions.csv`를 읽음. `dose_actual_mg_L`을 반올림 없이 사용 (20.1/40.2/60.3/80.16). 해시가 D02 기준과 다르면 화면 경고 |
| 기본 지역 선택, 교차지역 예외 명시 | 지역 기본값 언양. "두 지역 모두"를 고르면 "지역 간 전이 미검증" 경고 |
| 5/30분 동시 필터, 일반화된 다중 목표 | 5분·30분 목표를 따로 입력, 넣은 시점을 모두 충족해야 추천 |
| 기준 충족 최소 dose, 동률 규칙 | 최소 실제 dose. 동률이면 현재 pH에 가까운 목표 pH → 선택 시점 최대 잔류 탁도 낮은 조건 → 목표 pH 7에 가까운 조건 → condition_id 순 |
| 미충족·없는 응집제·외삽 거절 | 목표 미충족, 데이터에 없는 응집제, 원수 ±30% 밖은 추천하지 않고 "추가 Jar Test 필요". 응집제 선택지는 데이터에 있는 것만(현재 FeCl3) |
| 관측 데이터 보간 비활성화 | 관측값 사이 보간 없음 (관측된 조건만 추천) |
| 다른 조건의 문헌점 임의 보간 금지 | 문헌 주입량 직선 보간 제거. 원수 ±30% 안의 문헌값만 그대로 표시 |
| 문헌 쪽 확인 | 인용 문헌을 "제목 — PDF p.N"으로 표시 (기존 기능 유지·테스트) |
| 없는 날짜 질문은 자료 없음 | 질문 속 날짜를 실험일 기록과 코드로 대조해 없으면 LLM에 "자료 없음" 지시. 실험일 공란은 미기록으로 두고 채우지 않음 |
| 명시 요청의 두 지역 공통조건 | "두 지역 모두"에서 "두 지역 공통 조건도 찾기" 체크 시, 두 지역 모두 목표를 충족한 같은 설계조건(목표 pH·dose 수준) 중 최소 dose |
| Pareto | 근거 보기에 투입량–최대 잔류 탁도 Pareto 표 |
| TS/VS 운영 목적함수 제외 | TS/VS 자료를 추천에 읽지 않음 |
| 별도 개발 fixture로 검증, 최종 문항/Gold 하드코딩 금지 | `fixtures/synthetic_jar.csv` (가상 지역 SynA/SynB, 모든 행 SYNTHETIC 표시, 앱은 읽지 않음). 평가 문항·정답 미사용 |

입력 폼도 정리함: 필수(① 원수와 목표, ② 비교할 Jar Test) / 선택(③ 절감 계산, ④ 참고 정보) 구분, 라벨 "항목 (단위)" 통일, 입력창 테두리 대비 3:1 이상.

## 공개 파일과 실행

- `app/app.py`, `app/logic.py`: 제출받은 화면·추천·검색 코드 원본.
- `app/data/jar_conditions.csv`: 현행 D02와 바이트 단위 일치 확인.
- `app/.streamlit/config.toml`, `app/start_app.bat`, `requirements.txt`: 제출본 그대로 보존.
- C02 폴더에서 `pip install -r requirements.txt` 실행 후, 허가된 C01 내부 문헌 PDF를 `app/data/`에 별도 배치.
- `app/.env`에 본인의 API 키를 설정한 뒤 `app/start_app.bat` 실행. 접속 주소: http://localhost:8503. 키는 GitHub에 올리지 않음.
- 공개본에는 문헌 PDF·캐시가 없어 문헌 검색 전체 실행에 내부 자료가 추가로 필요함.

## 한계

- 원수 ±30%는 검증되지 않은 휴리스틱 (DATA_CONTRACT). 화면에도 표시
- 최소 dose는 pH 조정 약품 제외 기준이라 최소 총비용·탄소가 아님. 산·염기 실제 투입량은 미기록
- 탄소·전력 계수는 C01 값 그대로이며 E01/E02 반영은 C04에서 함
- 문헌 검색 대상은 C01과 같은 전체 PDF. L02 허용 목록 적용은 C03 평가 실행기 범위
